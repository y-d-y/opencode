启动一个新代理，以自主处理复杂的多步骤任务。

使用 Task 工具时，你必须指定 subagent_type 参数，以选择要使用的代理类型。

何时不应使用 Task 工具：
- 如果你想读取特定文件路径，请改用 Read 或 Glob 工具，以便更快找到匹配项
- 如果你要搜索特定类定义，例如“class Foo”，请改用 Grep 工具，以便更快找到匹配项
- 如果你要在特定文件或 2-3 个文件集内搜索代码，请改用 Read 工具，以便更快找到匹配项
- 如果没有合适的可用代理适合该任务，请直接使用其他工具

使用说明：
1. 尽可能并发启动多个代理，以最大化性能；为此，请在单条消息中使用多个工具调用
2. 一旦你将工作委派给代理，就不要自己重复该工作。继续执行不重叠的任务，或等待结果。对于后台任务，结果准备好后你会自动收到通知。
3. 当代理完成后，它会向你返回一条消息。代理返回的结果对用户不可见。要向用户展示结果，你应向用户发送一条文本消息，简明总结结果。输出中包含一个 task_id，你之后可以复用它来继续同一个子代理会话。
4. 除非你提供 task_id 来恢复同一个子代理会话（该会话会继续使用其先前的消息和工具输出），否则每次代理调用都会以全新上下文开始。从头开始时，你的提示应包含高度详细的任务描述，以便代理自主执行，并且你应明确指定代理最终且唯一一次向你返回的消息中应包含哪些信息。
5. 代理的输出通常应被信任
6. 明确告诉代理你希望它是编写代码，还是只做研究（搜索、读取文件、抓取网页等），因为它并不知道用户的意图。尽可能告诉它如何验证其工作（例如，相关测试命令）。
7. 如果代理描述中提到它应被主动使用，那么你应尽力在用户甚至没有要求的情况下使用它。运用你的判断力。
